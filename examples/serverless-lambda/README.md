# Salvo × AWS Lambda Example

基于 Salvo 的 serverless 运行时构建的 AWS Lambda 示例，演示基础路由、路径/查询参数、JSON 请求体、Lambda 事件数据访问、**流式响应**以及内存对象存储的上传下载。

A Salvo serverless example targeting AWS Lambda. It demonstrates basic routing, path/query parameters, JSON bodies, Lambda event access, **streaming responses**, and an in-memory object store with upload/download.

## 端点

## Endpoints

| 方法 Method | 路径 Path | 说明 Description |
| --- | --- | --- |
| `GET` | `/hello` | 纯文本问候 Plain-text greeting |
| `GET` | `/hello/{name}` | 路径参数 Path parameter |
| `GET` | `/greet?name=` | 查询参数 Query parameter |
| `POST` | `/echo` | 回显 JSON 请求体 Echo JSON body |
| `GET` | `/event` | Lambda 事件数据 Lambda event data |
| `GET` | `/stream` | **流式响应**，逐块发送 **Streaming response**, chunk by chunk |
| `GET` | `/objects` | 列出对象 List objects |
| `PUT` | `/objects/{key}` | 上传（内存存储）Upload (in-memory) |
| `GET` | `/objects/{key}` | 下载 Download |
| `DELETE` | `/objects/{key}` | 删除 Delete |
| `GET` | `/`、`/index.html` | 内置浏览器测试页 Embedded browser test page |

## 本地构建与运行

## Build & Run Locally

本示例使用 [`cargo-lambda`](https://www.cargo-lambda.info/) 构建和运行。

This example is built and run with [`cargo-lambda`](https://www.cargo-lambda.info/).

```bash
# 构建 release 产物
# Build the release artifact
cargo lambda build --release
```

启动本地模拟器（热重载）：

Start the local emulator (hot reload):

```bash
cargo lambda watch --release
```

启动后，函数被挂在 `cargo lambda` 的控制面模拟器下，**本地访问地址是**：

Once started, the function is mounted under the `cargo lambda` control-plane emulator. The **local URL is**:

```text
http://localhost:9000/lambda-url/example-serverless-lambda
```

> **注意 / Note**
>
> `cargo lambda watch` 会把函数挂在 `/lambda-url/<函数名>` 前缀下，因此所有 API 请求都必须以
> `http://localhost:9000/lambda-url/example-serverless-lambda/` 为基准路径，**不能**从根路径
> `/hello` 这类地址发起请求。
>
> `cargo lambda watch` mounts the function under the `/lambda-url/<function-name>` prefix, so every
> API request must use `http://localhost:9000/lambda-url/example-serverless-lambda/` as its base path.
> Requests must **not** be sent to root-relative paths such as `/hello`.

内置测试页会自动从当前页面地址推导基准路径，因此无论是在本地前缀下，还是在线上函数 URL 根路径下，页面里的按钮都能正确发起请求。

The embedded test page derives the base path from the current page URL, so its buttons work both under the local prefix and at the deployed function-URL root.

### 命令行调用示例

### Command-line Invocation Examples

本地运行时可用 `cargo lambda invoke` 直接调用函数：

With the local runtime running, invoke the function directly via `cargo lambda invoke`:

```bash
# 需要显式传入函数名（默认函数路由在本地模拟器中被禁用）
# The function name must be passed explicitly (the default route is disabled locally)
cargo lambda invoke example-serverless-lambda \
  --data-ascii '{"version":"2.0","routeKey":"GET /hello","rawPath":"/hello","requestContext":{"http":{"method":"GET","path":"/hello","protocol":"HTTP/1.1"},"routeKey":"GET /hello","stage":"$default"},"isBase64Encoded":false}'
```

## 部署

## Deploy

```bash
cargo lambda deploy
```

部署后通过函数 URL 访问，函数 URL 的根路径即为 `/`，无需额外前缀。

After deploying, access it through the function URL; the function-URL root maps to `/` and needs no extra prefix.

## 入口方式

## Entry Point

入口由 `#[service(start = init)]` 过程宏生成，与 Worker 示例使用同一套 `#[service]` 宏约定：在 `fn build() -> Router` 上标注即可，宏会生成平台对应的 `main` 函数。Lambda 端生成的是**流式**运行时（`run_with_streaming_response` + `handle_streaming`），因此 `/stream` 等无界响应会逐块转发，不会整体缓冲。

The entry point is generated by the `#[service(start = init)]` macro, using the same `#[service]` convention as the Worker example: annotate a `fn build() -> Router` and the macro emits the platform-specific `main`. On Lambda it generates the **streaming** runtime (`run_with_streaming_response` + `handle_streaming`), so unbounded responses such as `/stream` are forwarded chunk by chunk instead of being buffered.
